# 设计原则

Intuition  ·  Feedback  ·  Completeness  ·  Controllability

Mollu-Koru 是面向**电力系统拓扑建模**的业务组件库。下面四条原则指导着组件的每一个 API 设计和交互细节——无论是你作为消费方"拿来用"，还是作为贡献者"改代码"，都可以用它们来判断：这个设计对不对。

---

## Intuition 直观性

> 所见即所得，符号即语义。用户不需要学习成本就能看懂画布。

### 符号即设备

SVG 符号严格遵循国网标准电气符号（`mollu-design/assets/` 目录提供 41 个）。用户看到什么符号，就知道是什么设备：

| 符号 | 设备 | 语义 |
|------|------|------|
| ⚡ | 断路器 | 能分合、有两态 |
| 🔶 | KVT 电压互感器 | 测量电压 |
| ⬛ | 接地刀闸 | 安全接地 |

不做"抽象化"处理（比如把所有设备画成彩色方块）——拓扑图的第一价值是**可读性**，不是"好看"。

### 编辑态 = 预览态

**不**存在"编辑时一套、运行时另一套"的视觉差异。`<koru-graph-editor mode="edit">` 画出来的样子，和 `<koru-graph-editor mode="preview">` 运行时看到的样子完全一致。

唯一差异是编辑态会显示 Stencil（左侧符号栏）和属性面板——这是工具，不是画布本身。

### 命名自然

API 命名贴近电力行业术语 + Vue 生态习惯的混合：

```ts
setBindingConfig()       // "绑定"是电力系统术语（测点绑定）
setMultiStateConfig()    // "多状态"指断路器分合位
useKoruGraphEditor()     // Vue composable 风格
KoruTopologyPlugin       // Vue 插件命名
```

不用 `setDataSourceConfig` 或 `useCanvasEngine` 这种通用抽象名——消费方一眼就能对应到自己的业务场景。

## Feedback 反馈性

> 每个操作都要有即时、可见、不打断的反馈。

### 连线反馈

拖拽连线时：
- **可连接目标自动描边**：鼠标悬停到另一个节点的连接桩上，目标桩高亮 + 虚线圆圈提示
- **不可连接目标静默**：如果两个桩类型不匹配（比如输出桩连输出桩），线是灰的、拖不动——**不弹 alert 打断用户**

### 保存反馈

IndexedDB 自动保存：
- **成功**：画布右下角出现一个 `✓ 已保存` 的轻量 toast，1.5 秒后自动消失
- **失败**（比如 IndexedDB 满了）：toast 变红 `⚠ 保存失败`，但**画布本身的数据不受影响**（只持久化失败，编辑继续）

### 选中反馈

选中元素时：
- 节点：外框描边（`.selected` 类，默认 2px 蓝色虚线）+ 右上角显示旋转手柄
- 连线：整条线加粗到 2px + 端点变圆
- 多选：所有选中元素同步描边，画布下方显示 `已选中 N 个元素`

## Completeness 完整性

> 开箱即用不折腾，出错也不炸。

### 零配置可用

不调任何 `set*Config()` 也能跑起来：

```vue
<koru-graph-editor />
```

内置默认值：
- ✅ 基础 Stencil 分组（矩形 / 圆 / 文本 / 按钮 / 断路器 / 连线）
- ✅ 默认画布配置（800×600、10px 网格、灰色背景）
- ✅ 默认工具栏（保存 / 撤销 / 重做 / 缩放 / 全屏 / 模板 / 图库）
- ✅ 默认右键菜单（复制 / 粘贴 / 删除 / 锁定 / 对齐）

**消费方不需要先写 50 行配置才能看到画布。**

### 降级友好

任何外部资源加载失败，都不应该导致画布崩溃：

| 场景 | 降级行为 |
|------|---------|
| SVG 符号加载失败（404 / DOMParser 解析错） | 自动降级为 `custom-rect` 基础矩形，控制台 warn |
| 绑定数据源断线 | 属性面板显示 `--`，不抛异常 |
| `@arco-design/web-vue` 未安装 | 自动走零 Arco 路径，12 个自建组件顶上 |
| IndexedDB 不可用（Safari 隐私模式） | 关闭自动保存，内存模式继续编辑 |

### 双模式互通

一次建模，两种视图：
- `mode="edit"` —— 完整编辑器（Stencil + 属性面板 + 工具栏）
- `mode="preview"` —— 纯运行态（只有画布 + 可选动画）

数据格式一致，不需要"导出/导入"或两套模型。

## Controllability 可控性

> 用户永远在掌控。操作可撤销、数据可恢复、方案可切换。

### 撤销 / 重做

内置 undo-redo，快捷键 `Ctrl+Z` / `Ctrl+Y`。记录的操作粒度包括：
- 增删节点 / 连线
- 移动 / 旋转 / 缩放
- 属性修改（label / attrs / data）
- 批量操作（全选删除、对齐）

**不记录**的操作（应该"即时生效、不需撤销"）：
- 画布平移 / 缩放（viewport 不是数据）
- 选中 / 取消选中

### 持久化

默认 IndexedDB 自动保存：
- 每次操作后 1 秒 debounce 写入
- `persistenceKey` prop 控制保存的命名空间
- 刷新页面 → 自动恢复上次状态 → 用户看到的就是刚才离开的样子

### 零 Arco 可切换

两种依赖路径，**一行 import 的差异**：

| 方案 | 依赖 | 可用功能 |
|------|------|---------|
| 完整方案 | `@arco-design/web-vue` | 全部（含 KoruPropertyPanel Arco 表单） |
| 精简方案 | 零 UI 库 | 全部核心（12 个自建组件），属性面板自己写原生 HTML |

消费方可以在 `pnpm add @arco-design/web-vue` 和"什么都不加"之间自由切换，组件库代码**不分支**。

## 设计原则对消费方的意义

| 当你纠结... | 用这条原则问自己 |
|------------|----------------|
| "要不要加一个设置按钮让用户切换网格显示？" | 直观性：切换频率高吗？值得暴露给用户吗？ |
| "保存失败要不要弹一个模态框阻止继续编辑？" | 反馈性 + 完整性：toast 就够了，不能打断编辑 |
| "SVG 符号和业务自定义冲突怎么办？" | 完整性 + 可控性：`registerSvgGlob` 支持运行时替换 |
| "属性面板要不要内置一个 JSON 编辑模式？" | 直观性：目标用户（电力工程师）会不会用？ |

四条原则帮你做减法——**好的组件库不是功能越多越好，而是让最常见的路径像踩地板一样自然。**
